## 1. 业务目标与核心痛点

**目标**：在 GoModel Dashboard 的定价覆盖编辑器（Pricing Override Editor）中增加时间窗编辑能力，让 operator 能通过 UI 直接设定和管理模型的分时段计价（如 DeepSeek 峰谷定价、自定义时段折扣等）。

**当前状态**：
- **引擎侧**（`Pricing.AtTime` / `ModelPricingTimeWindow` / `mergeConfigPricing`）：**已完整实现**，对 catalog 和 config.yaml 的 `time_windows` 均正常消费。
- **配置入口**：仅有两处只读来源——
  1. 远端模型注册表 `models.json`（`provider_models` + `models` 元数据）
  2. 本地 `config.yaml` `providers.<name>.models[].metadata.pricing.time_windows`
- **缺陷**：两者均需手动编辑 JSON/YAML 文件，不可通过 Dashboard UI 增删改。

**痛点**：

1. **变更成本高**：调整时段报价需编辑本地 JSON/YAML 文件 → 重新加载 → 验证生效。频繁调价（如促销期、节假日调价）造成极大操作负担。
2. **无法即时生效**：文件修改需要 `POST /admin/runtime/refresh` 或重启，不可在 UI 点击即生效。
3. **不可见的窗口**：控制台 Models 页虽用 `*` 标记+悬浮提示显示模型有时间窗（`timeWindowHint`），但无法查看具体时段、无法修改、无法新增。
4. **与现有定价覆盖冲突**：当前定价覆盖（`/admin/model-pricing-overrides`）的 `Pricing` 结构体**不含 `TimeWindows` 字段**。覆盖一个模型的基础价后，`DropTimeWindowRatesOverriddenBy` 会**带走 catalog 窗口对该费率的折扣**——operator 必须意识这个副作用才能正确操作。

## 2. 业务流程与设计思路

### 2.1 核心流程

```
operator 打开 PricingOverrideEditor
  ├─ 基础价 → 标量编辑（已有）
  ├─ 阶梯价 → 表格编辑（已有）
  └─ ✨ 时间窗 → 新增编辑表单
       ├─ 查看当前窗口列表（来自 catalog / config / override 的三层合并）
       ├─ 添加窗口：选择 label + 一组 UTC ranges + 窗口内费率
       ├─ 编辑窗口：修改时间段或费率
       └─ 删除窗口
  → 保存 → PUT /admin/model-pricing-overrides
     → override 持久化到 DB（Pricing.TimeWindows 序列化进 JSON blob）
     → enrichment 读取时 override.TimeWindows 替换 catalog 窗口
```

### 2.2 三层定价组合逻辑（to-be）

保存后的定价覆盖包含 `time_windows` 时生效规则：

| 场景 | catalog 窗口 | override `input_per_mtok` | override `time_windows` | 最终行为 |
|------|-------------|--------------------------|------------------------|----------|
| 1. 只覆盖基础价 | 有 | 设了, 无 window | 无/省略 | `DropTimeWindowRatesOverriddenBy` 去掉被覆盖费率的折扣（当前行为） |
| 2. 只覆盖窗口 | 有或无 | 无 | 有 | override 的窗口**替换** catalog 窗口 |
| 3. 同时覆盖 | 有 | 设了 | 有 | override 窗口替换；基础价从 override 取，窗口价从 override 窗口取 |
| 4. 清空窗口 | 有 | 无（只设 `time_windows: []`） | 空数组 | DropTimeWindowRatesOverriddenBy → catalog 窗口对 override 涉及的费率失效 |

> `time_windows: []`（空数组）= 清除窗口。省略 `time_windows` 字段 = 保留 catalog 窗口（但 `DropTimeWindowRatesOverriddenBy` 仍对已覆盖费率生效）。

### 2.3 工作流（两个）

| 工作流 | 职责 | 触发 | 落点 |
|--------|------|------|------|
| **W1 时间窗编辑** | UI 表单 → 校验 → PUT admin API → 持久化 → enrichment 刷新 | operator 在定价编辑器操作 | `pricingoverrides.Pricing.TimeWindows` |
| **W2 窗口可视化** | 编辑器内预览时间窗 + 模型列 `*` 悬浮提示的实现 | 打开编辑器 / 渲染模型表 | `pricingoverridesLogic.timeWindowHint`（已有）+ 编辑器内时间段表格 |

## 3. 功能与数据模型

### 3.1 功能需求

- **F1** 定价编辑器新增 "Time Windows" 面板，可添加/编辑/删除时间窗
- **F2** 每个时间窗包含：`label`（只读 "off_peak" 或自定义）、若干 `utc_ranges`（days 多选 + start/end HH:MM 输入）、窗口费率（可覆盖 input/output/cached_input）
- **F3** 时间窗保存时做完整性校验：时间格式、不重叠(可选强制)、费率 ≥0
- **F4** 保存后若模型列 `*` 标记存在，立即刷新悬浮提示内容
- **F5** 已保存的 override 支持 `time_windows: []`（显式清空窗口）

### 3.2 非功能需求

- **NF1** 定价覆盖的 API 保持向后兼容：`time_windows` 为可选字段，旧 payload（无 `time_windows`）行为不变
- **NF2** 时间窗编辑不影响吞吐（编辑的是 operator 操作的定价覆盖，不涉及请求路径）
- **NF3** 时间窗编辑需全局权限（`global` scope），与现有定价覆盖权限一致

### 3.3 数据模型变更

**当前**（`internal/pricingoverrides/types.go`）：

```go
type Pricing struct {
    InputPerMtok           *float64      `json:"input_per_mtok,omitempty"`
    OutputPerMtok          *float64      `json:"output_per_mtok,omitempty"`
    // … 标量字段 …
    Tiers                  []PricingTier `json:"tiers,omitempty"`
    // ❌ 没有 TimeWindows
}
```

**改为**（新增字段）：

```go
import "github.com/enterpilot/gomodel/internal/core"

type Pricing struct {
    // … 原有标量字段不变 …
    Tiers                  []PricingTier           `json:"tiers,omitempty"`
    TimeWindows            []core.ModelPricingTimeWindow `json:"time_windows,omitempty"`
}
```

DB 表 `model_pricing_overrides.pricing` 是 `TEXT` JSON blob，结构兼容——无 `time_windows` 的旧行保持干净，新行带窗口 JSON。**无需 DB migration。**

### 3.4 API 设计

已有端点，payload 扩展现有 `Pricing`：

```
PUT /admin/model-pricing-overrides
{
  "selector": "deepseek-v4-flash",
  "pricing": {
    "input_per_mtok": 0.14,
    "output_per_mtok": 0.28,
    "time_windows": [
      {
        "label": "off_peak",
        "utc_ranges": [
          {"days": ["mon","tue","wed","thu","fri"], "start": "00:00", "end": "01:00"},
          {"days": ["mon","tue","wed","thu","fri"], "start": "04:00", "end": "06:00"},
          {"days": ["mon","tue","wed","thu","fri"], "start": "10:00", "end": "24:00"},
          {"days": ["sat","sun"], "start": "00:00", "end": "24:00"}
        ],
        "pricing": {
          "input_per_mtok": 0.07
        }
      }
    ]
  }
}
```

GET / DELETE 端点不受影响（`Pricing.TimeWindows` 字段空时 JSON omitempty 不序列化）。

## 4. 差异与决策附录

### 4.1 方案对比：嵌入 vs 独立端点

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A ★推荐** | 扩展现有 `/admin/model-pricing-overrides` 的 `Pricing.TimeWindows` | 1. 逻辑自洽（时间窗就是定价的一部分）<br />2. 一条 API 管全部<br />3. 提取"有效定价"时 `Pricing.AtTime` 已有完整逻辑 | 1. 前端表单变得复杂（标量+阶梯+窗口） |
| B | 新增独立端点 `/admin/model-pricing-time-windows` CRUD 窗口 | 1. 前后端都不改存量代码<br />2. 可独立设窗口粒度（不绑定 override） | 1. 分离了"定价"整体概念<br />2. 有效定价计算时需要组合两个来源<br />3. 增加 API 维护负担 |

### 4.2 边界与限制

- **无日历日期窗口**：时间窗是 **UTC 循环日程**（每周/每日），不支持特定日期的促销（如 2026-12-25 全天空闲）。此限制与现有 `ModelPricingTimeWindow` 设计一致。
- **仅 USD 货币**：定价覆盖默认 USD（`CurrencyUSD`），窗口费率继承此假设。无需货币字段。
- **不验证窗口重叠**：引擎 `AtTime` 优先匹配第一个窗口（按 `utc_ranges` 顺序）。编辑器可做但不强约束。
- **`window.ranges` 的 `days` 参数**：省略 = 每天（同现有解析逻辑），显式 `days: []` 也会被解析为无限制（if nil → no day filter）。

### 4.3 不建议做的事

- ❌ 不支持加载 catalog 窗口到编辑器再编辑保存（"编辑 catalog 窗口 → 保存为 override" 的 UX 过于复杂）。编辑器从**有效定价**（catalog+config+override 合并后）展示窗口预览，operator 可直接添加新窗口覆盖它。
- ❌ 时间窗编辑不需要 `POST /admin/runtime/refresh`——定价覆盖是 DB 持久化的，`enrichModelsLocked` 在初始化时自动读取。修改定价覆盖可通过 `RefreshProviderModels` 触发刷新或等后台周期刷新。

### 4.4 需要下一次实现考虑

- 时间窗"继承"语义：对 provider-wide 覆盖添加 window, 其下 model 级别覆盖怎么办？当前 `mergePricing` 的 selector 优先级链（exact > model-wide > provider-wide > global）已经支持：上层覆盖不设窗口时保留下层窗口。
