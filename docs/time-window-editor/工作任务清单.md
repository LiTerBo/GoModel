## 阶段 A：后端数据模型扩展（核心 API）

- [ ] A-1 `internal/pricingoverrides/types.go`：`Pricing` 结构体新增 `TimeWindows []core.ModelPricingTimeWindow` 字段（`json:"time_windows,omitempty"` / `bson:"time_windows,omitempty"`）
  - 测试：序列化/反序列化含窗口的 Pricing → JSON/KSON 正确；无窗口的旧 Pricing 序列化无 time_windows 键
- [ ] A-2 `internal/pricingoverrides/validation.go`：新增 `validatePricingWindows` 函数
  - 测试：
    - label 为空 → 拒绝
    - utc_ranges 空 → 拒绝
    - start/end 格式非法（非 HH:MM）→ 拒绝
    - day 名称非法 → 拒绝
    - window 内费率负数 → 拒绝
    - 有效窗口 → 通过
    - 空 `[]`（显式清空）→ 通过
  - 串联进已有 `validatePricing` 末尾（仅当 `len(TimeWindows) > 0` 时）
- [ ] A-3 `internal/pricingoverrides/validation.go`：`pricingOverrideEmpty` 函数确认包含 `TimeWindows` 为计算逻辑
  - 当前 `pricingOverrideEmpty` 使用反射 `structFieldsEmpty`，新增字段自动被包含
  - 测试：仅在 TimeWindows 有内容的 Pricing → 非空；空窗口列表 `[]` → 空
- [ ] A-4 `internal/admin/handler_model_pricing_overrides_test.go`：增 time_windows 的 upsert/read 测试 case
  - 测试：PUT 含窗口 → GET 读出保留窗口内容

## 阶段 B：后端覆盖合并行为调整

- [ ] B-1 分析 `internal/pricingoverrides/service.go` 和消费端（`usage/*`、`virtualmodels/balancer.go`）中定价覆盖叠加 `pricing.AtTime` 的调用链，确保带 TimeWindows 的 override 正确传递给 AtTime
  - 关键确认：ovrride 的 TimeWindows 进入 merged pricing → AtTime 取到
  - 测试：mock override 含窗口 → `AtTime(mocked time)` → 返回窗口价
- [ ] B-2 `mergePricing`（定价覆盖侧，非 config 侧）对 TimeWindows 的合并逻辑：有 TimeWindows 时替换 catalog 窗口；无 TimeWindows 时保持现有 DropTimeWindowRatesOverriddenBy 行为
  - 测试：override 有窗口 → merged pricing 窗口替换 catalog 窗口
  - 测试：override 有标量但无窗口 → 现有行为不变（catalog window 对该费率的折扣被丢失）
  - 测试：override 设 `time_windows: []` → 窗口被替换为空（无论 catalog 窗口如何）
- [ ] B-3 `pricingoverrides.View` 序列化确认 `TimeWindows` 能正确返回到 admin API
  - 测试：List 接口包含窗口数据
